## Recovery and build correction

An initial attempt to compile the rolling engine directly on the 4-core/3.6-GiB production host
used too much memory and already-full swap, temporarily making SSH and HTTPS unresponsive. The user
rebooted the Tencent instance. After reboot, all registered Raku services, Nginx, PostgreSQL, and
Redis were active; the old RakuXQ engine and data were intact, and swap use returned to zero.

The build path was then moved off production. GitHub Actions now builds in Rocky Linux 9, matching
the OpenCloudOS 9 runtime ABI. A prior Ubuntu 24 build was rejected before activation because it
required unavailable `GLIBCXX_3.4.32`. The server installer now uses an isolated staging directory,
verifies commit identity and both SHA-256 values, and only renames a fully working candidate into
place. Its emergency source-build fallback is single-job and low-priority.

## Serial A/B benchmark

Both engines used one thread, 64 MiB Hash, the same API adapter, and a 3000-ms budget per position.
The five positions were run serially so they did not compete for CPU or memory.

| Position | Old result | New result |
|---|---|---|

| Initial position | `c3c4`, depth 22, 480805 nps | `h2e2`, depth 24, 455494 nps |
| Tactical position | `b7b9`, depth 24, 623214 nps | `b4d5`, depth 24, 566919 nps |

All five searches completed with legal best moves, scores, PVs, and reproducible metadata. The
sample confirms compatibility and no operational regression; it is not large enough to prove a
universal Elo gain. Different best moves and scores are expected from the new program/network pair.
