## Delivered behavior

- Replaced the homepage's FEN/NNUE-first hero with plain player language: photograph or upload a
  position, let RakuXQ understand it, and receive a strong reference move within seconds for
  review, study, and learning. The first screen now states the non-commercial and no-gambling
  boundary explicitly.
- Production evidence identified the apparent Lab autoplay failure: the latest analysis request
  returned HTTP 401 because the current tab had no API Key. The old toolbar only reflected that an
  engine existed on the server, so the control looked actionable without disclosing the missing
  authorization prerequisite.
- Enabling engine-red or engine-black now checks the current tab's credentials first. If a hosted
  deployment requires authentication and the field is empty, the Lab opens Settings, focuses the
  Key input, explains the authorization boundary, and remembers the requested action. Applying the
  Key resumes that action without storing the secret in the URL, game record, or persistent browser
  storage.
- A single enabled side waits for the human opponent and responds automatically on its own turn.
  With both sides enabled, analysis and moves continue sequentially, never concurrently, until
  checkmate, Xiangqi stalemate (a loss for the immobile side), draw, or manual disable.
- Manual board moves are blocked while the current side is engine-controlled. Authentication
  failures stop that side instead of retrying indefinitely, and distinguish missing, expired, and
  engine-access-denied keys.

## Access boundary

The deployed Pikafish/NNUE network remains limited to the maintainer's authorized personal Key for
non-commercial validation. This release makes that existing boundary visible and actionable; it
does not embed a Key in the website or broaden engine access to trial and customer keys.
