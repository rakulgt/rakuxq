## 内部汇总单元的发现与修复

发布验收发现内部摘要最后更新在 23:31（服务器时间），timer 仍运行但 oneshot 报 OperationalError。
现有 ProtectSystem=strict 沙箱不允许 SQLite 只读 WAL 连接在辅助文件消失后重建 -wal/-shm。
它不是识图/出招接口错误，但导致汇总过时；没有用旧文件冒充新鲜验收。

先将原 `rakuxq-ops-summary.service` 备份到上述发布备份目录，再安装跟随本记录入库的 infra 单元：
仅允许私有 public-metrics 目录中的辅助文件写入，同时将主 SQLite 文件显式 ReadOnlyPaths 绑定，
导出器继续 mode=ro，只输出原有汇总白名单。没有修改源表、业务计数、采集范围、权限主体或保留期。
daemon-reload 后仅启动本 oneshot，未重启 API 或其他项目。修复后 Result=success、ExecMainStatus=0，
摘要五分钟内刷新、rawEventsExported=false；0640 / rakuxq:raku-insight，消费者可读、nobody 不可读。
导出两个测试（含新增沙箱保护回归）及 Ruff 通过；主数据库双重只读要求已写入源码测试。

统计 preflight 通过，但 manifest 仍 configured：PV/UV、全请求失败分母、独立测试过滤和完整路径仍缺失。
一次实际公网烟测按原匿名口径计数，隔离原图回放不计；不宣称统一分析整体 verified。
