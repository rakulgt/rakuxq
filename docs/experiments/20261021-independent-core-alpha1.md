# 自主核心第一阶段：实现与证据

本次交付是可运行、可训练、可复盘的**独立实验核心**，不是已经达到线上棋力的替代版本。应用版本仍为 `0.5.7a1`；不因实验代码进入主分支就切换生产引擎。

## 已实现

- 独立 C++17 棋盘、走子、将军/终局检测、迭代加深 Alpha-Beta、捕获静态搜索、缓存走法排序、有界时间/节点/深度、异步停止和 UCI。仅单线程，支持 MultiPV 1/2。
- 自定义 `RAKUXQ_NNUE_V1`：1262 个输入特征、32 个隐藏单元、量化整数与增量累加器。从随机参数开始训练，不兼容或导入 Pikafish 权重。这是小型研究架构，不能把“使用 NNUE”理解成“达到成熟 NNUE 引擎棋力”。
- 合成自对弈 → 按整盘隔离训练/验证、清除跨组重复局面 → 训练 → 量化导出 → 重新加载 → 下一轮自有模型自对弈 → 新候选 → 成对换先评测。下一轮模型须有匹配摘要、来源及训练回执；不接收任意外部权重或客户短期审计。
- 竞技场使用现有项目规则独立验证招法，保存开局、完整逐手招法、最终 FEN、时间、版本和摘要。重复或步数截止保留为未裁定；既不伪造和棋，也不从区间中排除未裁定的不确定性。
- 九份相关源码有合法语言元信息和清单检查；源码/参数/资料分别可追溯。元信息检查与项目独立编写声明**不是法律无侵权鉴定**；通用依赖仍按各自许可证使用。

核心没有移入第三方引擎实现，也没有使用 lgtXQ 旧代码。固定 BSD-2-Clause `xiangqi.js` 只作为外部测试判据；兼容测试复用本项目已有 MIT HTTP/UCI 适配层，不把适配器的历史类名当成核心实现来源。

## 客户端保持不变

五个现有公开 POST 请求的结构、默认值、鉴权头和成功媒体类型已冻结：

| 接口 | 保持的作用 |
| --- | --- |
| `/v1/recognitions` | 图片识别 JSON |
| `/v1/fen` | 图片识别纯文本兼容 |
| `/v1/solve` | 图片识别与解题融合 |
| `/v1/solutions` | 面向客户端的 FEN 解题 |
| `/v1/analyses` | 原底层解题兼容 |

没有增加必填参数、深度或 pro 设置，也没有调整 auto、搜索时间、候选数、FEN 空格、Key 或免费 Lab 边界。原简化 `fen` 是布局加空格及 `w/b`，`full_fen` 保留六字段。

真实二进制经既有适配器验证中文招法、红方固定评分视角、KO、终局、主要字段和免费同源 Lab。特别保留原有区别：`/v1/solutions` 顶层 `status=accepted`，搜索状态在 `analysis_status`；`/v1/analyses` 和 Lab 原状态为 `completed`。不为通过新测试改写旧接口。

## 验证证据

- 本机真实 Windows 程序：25 项候选测试通过；不是缺少编译器时跳过 native 测试的结果。包含唯一应招、将死、强制杀棋、MultiPV、停止、无效局面/模型拒绝、极端整数边界、量化与增量一致性、来源链和旧接口接入。
- 自主走子与固定外部规则判据在 964 个局面上一致；标准开局 44 个合法着法，`perft(2)=1920`。既有应用规则另有 724 局面差分测试。有限样本通过不证明所有象棋规则正确。
- Linux/Windows CI 同时构建、测试、规则对照、训练、量化重新加载；既有 Python 3.11–3.14 API 和 Web 测试仍独立执行。具体运行记录见下方链接。
- 新增参数上界测试发现并修正了极端有符号整数取绝对值的问题；错误参数现在拒绝加载，不能静默变成合法权重。
- 源码元信息检查通过九份文件；五个请求契约快照检查通过。原应用测试基线为 270 项 pytest、37 项 unittest、20 项 Web。

### 两轮实际训练与小样本试赛

Windows 实验固定种子 `20261021`，每次自对弈搜索 10 ms、训练 20 轮；模型 A 为手工评估搜索生成资料训练，模型 B 为模型 A 搜索生成资料重新训练，二者均从随机初始化拟合。

| 项目 | 模型 A | 模型 B |
| --- | ---: | ---: |
| 自对弈盘数 | 8 | 8 |
| 生成记录数 | 383 | 254 |
| 去重/防泄漏后的训练局面 | 281 | 184 |
| 验证局面 | 95 | 63 |
| 验证均方误差 | 0.142540 | 0.000186 |

两轮目标值和资料分布不同，误差不可直接作为跨轮棋力比较。它们拟合的是弱搜索的启动标签，不是最优着法真值；验证集也不是独立棋力盲测。

实际模型摘要：

- A：`f4f1aae89b1d67e03346398299e61b30faaeb6c0c636b1984cf8a3d85e06e27c`
- B：`de0365ecb6779e6443395cb5bd32ede0a51fc500b679fc45e1bc4c84ae951dca`
- 资料生成程序（CI `a094678`）：`6a6563002788a2a3732d3843d660267b6074f24c42ba2ae536284f9089076b16`
- 对弈程序（CI `cea85c1`，含参数边界修正）：`69f87f8221aacd456440573d6037eea51ab304762250920b046ba97d887b350e`

同一程序加载两代网络，以 100 ms/手、单线程、16 MiB Hash、两个开局成对交换红黑、每盘最多 80 个半回合（单方走一步计一个）试赛：B 为 **0 胜、2 负、2 未裁定**，完整成对裁定数为 0，不能据此发布 Elo 或声称统计性强弱结论。253 次搜索的本机程序往返平均约 97.6 ms、最大约 136.3 ms，不是手机网络时延或生产 SLA。

本轮结果不足以晋级，而且已出现退步信号；**不采用模型 B 替换任何生产模型**。资料、参数、完整回执和棋谱均位于忽略的实验目录，不进源码 Git；摘要用于核对，不代表已发布商用模型。

Linux 服务器还在隔离候选目录完成了串行、低优先级的编译和连续两轮合成训练加载实验，没有安装新生产依赖、启动常驻训练、读取客户原图或变更当前服务。最新版候选源码为 `8ee93b4b48c65988a46996839098eedb6c72617b`，服务器原生编译程序摘要为 `861448e2d16ba762869877a5779e9a8198e74e9b3d86dca6747b6f2290cf6a5f`；开局 perft 与第二轮模型的两手增量校验均通过，生产健康与原引擎身份保持原样。

## 未达成的目标与继续门槛

1. **自主视觉尚未完成。**当前生产视觉权重仍沿用基线；需要权利清晰的视觉训练资料、自有参数和独立整盘盲测，不能用接口未改来证明识图自主化。
2. **同预算棋力不退步尚未证明。**当前小型网络和基础搜索不是成熟 Pikafish 等价品；必须继续研发并有足够规模、可复盘的独立对照。不能靠增加搜索时间伪装同预算提升。
3. **规则与工程尚未完成生产认证。**完整长将/长捉历史裁决、长期稳定性、并发隔离、内存/延迟和回滚仍需专项验证；单张 FEN 缺少历史，不保证历史裁决。
4. **持续改进不是自动变强。**已具备离线迭代工具，尚未启用定时训练或自动晋级；候选即使完成训练、验证损失下降，也不授予线上替换权。
