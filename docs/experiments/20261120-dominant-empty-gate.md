# 单个弱空位误拦：诊断与回归证据

2026-11-20，Asia/Shanghai；v0.5.8-alpha.3。PROJECT NO_CHANGE：修复门控实现，不改变拒绝猜测棋子、可审计修正及客户端契约。

## 已确认的触发链

最近连续六次融合请求均 HTTP 200 / review_required / analysis_status=not_started。
定位约 0.57、明确棋子最低约 0.902 均过原门槛，局面也通过引擎边界校验；唯一未过的是
第 10 行第 8 列的空位。模型原始最优类别都是 `.`，分数分别为
0.608414、0.518085、0.542005、0.582066、0.605670、0.588352；次优类别分数分别为
0.107802、0.128945、0.130081、0.132105、0.116866、0.119238。
原空位门槛 0.75，既有单空位确认还要求至少 0.65 / 领先 0.50，故六次均被拦在 NNUE 之前。

这证实了门控缺口，不证明低分一定由某种 UI 图标造成，也不代表合法性本身能证明视觉正确。

## 修复与保护

保留既有高领先确认；新增一个有界分支：全盘可见、无未知 x、全盘只有一个弱的非主帅格且原候选为空、
所有明确棋子原始和有效分数均至少 0.90、空位原始分数至少 0.50、领先至少 0.35、次优最多 0.15
且空位至少为次优的三倍、没有阻断性局面异常。全局定位、行棋方、联合置信和引擎边界校验仍独立执行。

该分支只确认原本的空位，不将明确棋子删除或交换阵营；有效决策分设为 0.75，不伪称新的校准概率。
完整响应保留原始分数、领先差、次优分数、明确棋子的最低原始分数、确认策略和既有
LOW_CONFIDENCE_EMPTY_CONFIRMED 警告。不新增模型调用或慢速视觉回退。

融合接口的同一 display_text 字段改为具体原因：定位、空位、棋子、行棋方或局面异常。
未通过仍不启动引擎，不向用户假装成功，也不一律归咎于拍照。

  弱棋子、有效棋子分不足、多弱格、未知格、部分棋盘、非法局面、明确棋子候选等反例。

- 在原服务器内通过实际 ONNX provider 重跑六张失败原图：均 accepted，棋子和 FEN 与原候选完全一致，
  原始证据保留，每图仍仅一次布局推理；另十张近期已通过原图的棋子/FEN/accepted 状态保持一致。
  这十张是相邻成功对照，不等于十种独立局面或视觉盲测集。
