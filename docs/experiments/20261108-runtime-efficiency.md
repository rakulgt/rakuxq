# 2026-11-08 适配层与并发效率对照

范围为生产 A 的请求调度、视觉后处理和 UCI 适配层。未改 Pikafish 程序、NNUE、ONNX 权重、置信门槛、搜索预算、Key 权限或公开接口。不是自主引擎 B 晋级或全面棋力评测。认知基线 NO_CHANGE。

## 原因与边界

在服务器内仅汇总最近保留的 120 次成功图片解题：全部请求的搜索预算为 9000 ms，搜索中位数 8978 ms、应用中位数 9284 ms、请求接收中位数 32.5 ms；单条最大接收 2622 ms。这是存量成功样本，不是全量失败或端到端客户端网络测量。主要耗时确实是请求的搜索，不是上传或遗留模块；不能把减少搜索时间称为无损优化。

原服务只有一个串行 UCI 进程，同时间的其他分析会排队；同步视觉调用还阻塞 ASGI 事件循环。改为最多两个独立进程租约（每个仍为一线程/64 MiB Hash），每个租约覆盖完整首选/备选阶段。空闲时 LIFO 复用同一暖进程，避免顺序对弈无故轮换 Hash；不缓存旧图/旧答案，不自动换引擎。

## 对照方法与结果

- 使用同一台 4 vCPU 主机、同一个安装运行时、同一 Pikafish `dev-20261001-1c66b9b2` 和网络 SHA-256 `6b74ac7bbd299dc26a17803135b616eda9248bef0cbfc7b811bfcf981832ba29`。只启动隔离基准进程，不计入公开统计、无 Key 扣次。工具为 `scripts/benchmark-runtime.py`。
- 两道不同题同时请求、每题 1500 ms：单槽两题共 3005.502 ms，双槽共 1506.743 ms；搜索各自均 1501–1502 ms，均有合法着法。单/双槽引擎进程 RSS 合计约 195.55/331.86 MiB（不是整项服务峰值，也不能直接拿来计算用户容量）。
- 初始双槽测试的两个深度为 21/21，单槽为 21/23；第二题可受前题 Hash 与调度影响，开局同分对称着法也可能不同。本证据支持减少并发等待，不证明每局达到完全相同深度或统计棋力等强；没有降低每题预算、替换评估或剥离规则。
- 五个固定局面分别从冷进程执行 1500 ms 的单题原/新版对照，最佳着法和评分一致，包括经典 KO(2)、唯一解将与无着法终局。普通两题仍约 1503–1505/1503 ms，不能宣称单请求时延翻倍改善。
- 规则准备五局面平均耗时的 40 批中位数由 1.125 ms 降至 0.758 ms，约降 33%；这只是一毫秒级模块，不是全接口降 33%。候选几何生成保留屏障、马腿、九宫和被将检查，首选/备选复用同一准备结果。
- 固定六张留存原图，每张五次：去掉随机请求标识和计时后，FEN、置信度、原候选、修正证据等完整识别语义摘要六组全部一致。样本在本项目服务器内处理，没有复制原图到开发仓库或训练库。视觉中位数在约 279–390 ms 波动；存在同时段业务负载，不以这组串行样本宣称确定的视觉加速百分比。
- 前后 OpenAPI 去掉版本号后的 SHA-256 均为 `c195617b4896ffdf1c6455bc08b06aa57913b230861703d72b5010d8c8041f2a`；请求/主要返回结构不变。

## 清理与质量修正

删除两段重复的全 90 格字形特征提取循环，改为同候选内按需复用；删除仅旧测试使用的诊断包装及未使用的候选 warped 图像保存字段；移除重复双阶段安全检查、重复中文 PV 转换和无作用的锁内 pass 分支。原颜色诊断与几何回退仍在实际路径，不能当作废旧算法删除。实验 B 的源码、部署、限期和历史记录保留，不因本次清理而删除。

同层 UCI 多次评分时采用所选着法最新报告，避免拿先前 lowerbound 覆盖后续 exact 值；旧引擎读取线程绑定旧进程/旧队列，防止恢复时残留 EOF/文本污染新会话。新增并发租约、退出等待/防复活、错误归还、暖 Hash 复用、事件循环响应、语义一致和评分更新回归。规则与固定浏览器规则在 3176 局面一致。

生产启用、最终版本、资源实测、权限和回滚证据以本次实际部署记录为准。原统计 configured 与其全请求分母/测试过滤等缺口不因性能基准而视为修复。
