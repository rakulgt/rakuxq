# 白点/光标空位：同图像素占位复核

2026-11-20，Asia/Shanghai；v0.5.8-alpha.4。用户要求将已离线验证的方法接入服务器并同步 GitHub。
PROJECT NO_CHANGE：原视觉 provider、可审计门控和不删除明确棋子等边界不变。

## 接入的实际能力

新增原生 OpenCV 实现 `providers/occupancy.py`，不是新训练网络、大模型服务或基于棋理猜空位。
它只消费当前透视校正图、原始类别和分数，不保存图片，不访问外网，也不跨请求复用棋盘或答案。

只有 alpha.3 的 `dominant_empty_strong_pieces` 低分空位分支经过原先全部数字、完整性和局面检查后，
才调用本复核；既有高领先空位分支和普通图不增加特征计算。低分分支现在必须取得独立像素支持才能提升决策分，
不再只依靠领先差及其他棋子的高分。所有定位、行棋方和引擎安全检查继续生效。

1. 以每格 37×37 区域的环带提取 HSV 直方图，内半径 9、外半径 16，避开小型中心光标。
2. 从同图选至少 3 个原始分至少 0.80 的空位、至少 2 个原始分至少 0.90 的明确棋子作参考。
3. 每个已知棋子必须通过留一检查：不能把自己的特征当参考，若它更像棋盘空位，则本图材质/配色不可用于独立确认。
4. 比较目标与两组各最近最多 3 个参考的平均 Bhattacharyya 距离。确认空位需空位距离最多 0.45，
   且与棋子距离相比至少领先 0.15；相反证据投 occupied，否则 uncertain。距离不是正确率。
5. occupied、uncertain、参考不足或不可分时不提升有效分；保留原候选而要求复核，绝不把明确棋种改为空。

完整响应保留参考数量、留一错误数、比较距离、门槛、原因与耗时。成功仍使用既有确认警告；
未确认也保存未应用的检查证据。原始 softmax/候选不覆盖，0.75 仍只是可审计的有效门控分。
本方法依赖同图高置信参考，不能被描述成完全脱离原模型的通用占位分类器。

## 证据

- 原图人工/大模型目视并经用户确认：争议交叉点为空，上面是白色小圆环；下方圆形图案是棋盘外“支招”按钮。
  六张截图为同一局面的近重复，不当成六个独立场景。
- 候选程序在服务器审计池内重跑该六张原图，六次均取得像素确认、留一错误为零；
  比较领先最小 0.272621，原棋子及 FEN 不变，布局推理仍每图一次。
- 另取 10 个不同 FEN 的近期成功原图，自动通过状态、棋子和 FEN 保持不变。
  这是原模型结果对照，不是人工标注整盘准确率。
- 六次内存反事实：把同图真实棋子棋面贴到目标位置，但故意保持原始空位候选，
  复核全部投 occupied 并拒绝确认。没有修改用户原图、生成长期样本或写公开统计。
- 该次十六图识别中位 285 ms、最大 318 ms；低分六图复核中位 6.1085、最大 6.329 ms。
  上一轮有负载波动时复核最大 9.702 ms。这是处理耗时观测，不是固定公网加速或硬时限承诺。
- Python 333 项、Web 20 项、3176 局面规则对照、Ruff、Mypy 27 文件和既有 ONNX 摘要通过。
  新增合成测试含：有/无中心光标、原候选为空但像素有真棋子、低对比不可分、参考不足、部分棋盘、
  明确棋种保护、有效分/原分分离，以及正常路径不调用探针。

本组自动通过覆盖为 16/16，但整盘零错误率及自动通过结果精确率没有足够独立人工标注，不能给出可信百分比。
低对比材质、特殊尺寸、小型棋子、多弱格和其他光标形态仍需独立盲测；不承诺所有新样式零误判。
本次没有训练、换模型、增加第三方权重或改变客户参数。原图继续只按原 12 小时审计规则保留。
