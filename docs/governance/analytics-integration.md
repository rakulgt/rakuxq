# 统一运营统计接入协议

协议版本：1.1.0。适用根治理 B.11.2。具体实例策略以 `registry/analytics-policy.json` 为准，项目/服务器事实仍由既有注册表与 inventory 维护。

## 范围与职责

已登记、自有且正式运行的项目默认纳入；未来服务器采用相同接入契约。外部委托、隔离租户及尚未核验的资产不得仅因同机或同域自动采集。公开性与运营数据访问权限分别管理。新服务器上线与产品迁移不重建产品身份。

自动接入须保留项目更严格的隐私承诺和数据契约。明确禁止行为追踪的产品不得自动注入浏览器行为脚本，先核验允许的无个体识别汇总及健康指标；未确认范围保持 planned 并显示约束，不自行批准例外，也不从覆盖报告中隐藏。中心默认保留期是上限，已有数据更短时取更短者；迁入中心或生成副本不构成延长保存授权。

默认尽可能覆盖必要关键路径，包括受控页面/路由、功能使用、关键步骤、开始/提交、成功/失败及结果使用。事件数量不证明完整性；字段仍最小化，不默认全量 DOM 自动采集、输入内容或录屏。留存和关联路径需要允许且稳定的产品内标识，条件不成立时明确不可用。

## 既有承诺冲突决策

发现冲突后准备具体、可审阅提案，列出原承诺来源、拟修改文字、准确事件/字段/标识/用途/保留期、预期分析收益、替代方案与生效条件。施工阶段通过人类问题弹窗提出，平台建成后使用内部决策待办及弹窗。

负责人或其明确授权者选择保留、批准该版本修改或暂缓。批准记录绑定提案版本/摘要、范围、审批人和时间；取消、关闭、沉默、已读均不构成授权。状态可为 detected、pending-decision、retained、approved-pending-activation、active 或 deferred；这些是变更决策状态，不替代项目接入 manifest 的验收状态。

批准后先完成产品基线与公开说明、适用告知/同意及技术开关/字段验证，再记录生效时间并启用。内部管理员批准不能代替用户侧必要条件。增加范围、用途或保留期须重新决策；未决定或未生效时原承诺继续适用，其他项目安全工作继续。历史不补造、不追溯扩大授权。

统计底座负责事件与分析查询；内部工作台负责准入、项目授权、消息、审批和质量展示。原始统计不承担广告计费、订单、收入或资金账目职责。广告接入及商业使用另行授权。

## 单一事实来源

- `registry/projects.yaml`、`registry/services.yaml`：项目归属、路径、域名、部署映射。
- `registry/analytics-policy.json`：统计中心身份、默认保留期、报告时区与隔离排除。
- 项目根 `ANALYTICS_INTEGRATION.json`：项目状态、环境、适用级别、事件契约与证据引用；禁止凭据。
- 项目部署记录：逐次采集验收、过滤和权限结果。
- 工作台运行数据库：申请、审批、成员授权、站内通知及内部分析数据；禁止提交 Git。

独立仓库须携带由控制工作区生成的协议快照与源摘要，或固定版本的可访问引用；不依赖其他产品源码运行。可用共享检查器必须通过版本化工具或规范快照交付，不依赖父目录在生产存在。

## 接入级别与状态

- `basic`：访问/使用次数、访客估算及适用来源/设备；API 或客户端以适用的请求/任务指标替代页面访问。
- `business`：在基础统计上增加项目明确的核心流程、成功、失败和有限错误分类；静态网站选择适用 CTA，不虚构后端成功。
- 状态为 `planned`、`configured`、`verified`、`suspended`、`exception` 或 `not-applicable`。只有取得真实采集证据才可设置 verified。未接入不能显示为零流量。
- exception 与 not-applicable 必须有人类批准依据、责任人、具体理由及到期复核。Agent 不能自批；适用性按组件判断，不能用“静态站”免除网站基础统计。

## 最小事件契约

稳定 `projectId`、`environment`、`release`、`eventName`、`eventVersion`、发生时间及事件去重 ID。采集服务校验网站标识、精确主机/路径归属和字段白名单；这些公开标识不作为用户认证秘密。主站与路径子项目采用最长匹配归属，别名域名归同一产品，避免重复上报和归属污染。

业务事件注明触发条件、来源、计量单位、成功定义及去重规则。点击、开始、成功、失败分开；服务端可确认的结果由服务端确认，携带去重 ID 防止重试重复计数。报表保留分母；变更事件语义时提升契约版本，不静默混算。

一期不承诺部署跨产品个人级归因。匿名访客为估算，跨产品人数不能直接相加称为家族独立用户。留存须说明身份稳定性与观测窗口；低样本同时显示绝对量，变化相关性不充当因果证明。

## 隐私与采集质量

默认排除密码、Token、Cookie、邮箱、手机号、输入文本、聊天内容、文档正文、完整错误堆栈及业务标识。URL 先去敏感 query/hash，动态个人路径归一化，标题采用受控页面名；来源仅保留安全范围。认证回调、账号、邮件验证与恢复页面默认不采集。不得先收集敏感字段再事后清洗。

会话录像、跨产品个人关联及广告追踪默认关闭。项目隐私说明如实描述采集，适用同意及退出机制在接入时按项目确认；不宣称技术上不可察觉。开发、自动化验收、内部巡检和生产访问分别标记；不能默认把全部运营团队真实使用排除，过滤规则需可解释。

质量状态至少区分：未接入、已配置未验收、正常观测、疑似异常、不适用。低流量无事件不是故障证明；用独立合成检查验证链路，并将合成事件排除业务报表。浏览器采集可能被阻止，访问日志仅作不同口径的辅助证据。

统计请求异步、超时受控，失败不阻断业务；不为了采集放开跨域任意访问或扩大凭据权限。采集入口与管理/查询入口分别保护；不得把上游统计账号、管理 API 或公开分享作为后台权限旁路。

## 发布与验收

1. 确认资产、项目 ID、主机/路径、环境和事件契约；受控预览与敏感项目另审采集范围。
2. 模板与构建入口纳入基础接入，前后端成功事件使用同一契约。
3. 发布前运行统计治理检查，严格模式只对本次交付项目生效；历史全域审计可报告迁移缺口，不自动把缺口当成已通过。
4. 正式环境发送隔离测试事件，确认后台收到正确项目、环境、版本与时间；检查重复、敏感字段、过滤及适用转化路径。
5. 直接访问查询/导出/上游管理接口，验证匿名、待审批、拒绝、停用及越权账号被拒绝。停用阻断后续请求，而非只隐藏菜单。
6. 将验证时间、版本、证据文件写入 manifest，逐次结果写入部署记录。失败优先回滚本项目接入，不回滚或清理其他项目。
7. 既有项目逐项补齐并在下次正式发布复核。没有历史行为数据不得生成历史曲线；日志导入记录来源、时间与口径。

## 运营使用

每个产品指定指标维护责任人，定义核心成功结果、最低必要质量指标与报告周期。发布记录关联产品版本；运营改进记录包含观察、样本、假设、行动、责任人、预期指标和复查时间。保留用户反馈入口，统计只能指出现象，不替代对原因的验证。

保留期清理须先验证日汇总与恢复能力，采用明确项目范围和可回滚方案；该协议不授予生产数据删除权限。备份、访问日志和审计记录分别制定保留策略，不能把事件清理等同于所有副本已删除。
